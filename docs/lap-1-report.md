# 1 周目の報告（2026-10-17）

練習用メモ API で、工場の最小試作を 1 周回した結果。設計の正本は suisya-systems/factory-notes リポジトリの design/grand-design.md（以下「設計書」）。

この文書での言葉:

- **1 周目 / この周**: 2026-10-17 に回した、工場の最初の実行（lap）。lap はオーナーが予算を決める工場の 1 回の実行で、その中の全モデル呼び出しの費用を lap 台帳（`.factory/lap-ledger.json`）に積む。
- **オーナー**: 工場の予算と入口の承認を決める人。この周では repository owner の happy_ryo。
- **作成担当**: この工場を実装し、この報告を書いたエージェント（claude-org のワーカーとして動いた Claude Code）。**実行担当**: モデルの API に出られる端末で工場のコマンドを叩いた担当（claude-org の窓口役）。手順は [lap-1-runbook.md](lap-1-runbook.md)。
- **前提 1〜3**: 設計書の末尾「試作で最初に確かめる、一番危うい前提」の番号。1 は「作る役にシナリオを見せなければ合わせ込みは防げる」、2 は「人に戻らなくても、やり直しで収束する」、3 は「費用を全量計上できる」。
- **inSpec**: 隠しシナリオごとに、下書き役が「この振る舞いは仕様に書いてある」と申告した印。通過率をこれで分ける。
- **カナリア**: 隔離の確認で保管庫（隠しシナリオの置き場、`.factory/vault/`）に置くランダムな文字列。作る役の返答やファイルに出たら漏れと判定する。

## 結論

- 1 周目は通った。入口の承認 → 作る → 確かめる → 出す → 本番を見る、が人の手を介さずに進み、作る役は 1 回目で合格した（隠しシナリオ 15/15、LLM 判定も合格）。工場が積んだ commit `6d33b99` は、実行担当が suisya-systems/factory-practice-memo の main に送った（そのリポジトリの履歴で参照できる）。
- 費用は 1 変更で $0.51、隔離確認を含む 1 周全体で $0.88（いずれも `claude -p` が返す `total_cost_usd` の合算で、クライアント側の見積もり）。設計書の決定 1 にある見立て「1 変更 $7〜24」よりはるかに安い。ただし、やり直しが 0 回だった周での値である。
- 一番危うい前提 1（シナリオが仕様から推し量れる）は、懸念どおりの形で観測された。下書き役が仕様を細かく書いたため、15 本のうち 14 本の振る舞いが仕様に書いてある。前提 2（やり直しで収束する）は、1 回目で合格したため実走では試されていない。

## 隔離の確認（作る役から隠しシナリオが読めないこと）

- 方式: 作る役の `claude -p` を bwrap で包む。中から見える `/` は読み取り専用で、`$HOME` は空の tmpfs に置き換え、そこへ必要なものだけを戻す（認証ファイルは読み取り専用、`~/.claude.json` は許可したキーだけの使い捨ての写し、CLI 本体と Node）。ほかに、`/tmp`・`/mnt`・`/run/user`・`/var/tmp` を隠し、プロセス名前空間を分け、書き込めるのは自分の作業場所だけにする。保管庫と記録は `$HOME` の下になければ工場が起動を拒否するので、必ず隠れる。プロンプトでの「見るな」には頼らない。
- 作る役が書いたアプリのコードも同じ sandbox で動かす（判定のテスト実行と本番）。アプリのコードが実行時に保管庫を読みに行く経路をふさぐため。
- 実走での確認: 上の「隔離の確認 3 回目」。読ませようとして失敗した記録は `.factory/runs/lap1-probe/isolation-probe.json`（実行した手元の状態ディレクトリにあり、git 管理外）。
- 作る役へ返す不通過理由は、入口で承認された 1 行要約だけ。LLM 判定の理由文は返さない（オーナー決定）。理由文は監査用に隠しの記録 run.json にだけ残す（2026-10-17 の実行の後で追加した変更なので、その実行の run.json には入っていない）。

## 既知の限界

- 隔離: 作る役は認証トークンを読める（ログインに要る）。それを使ったモデル呼び出しは台帳に乗らない。ネットワークは共有なので、作る役は外へ出られる（モデルの API に要る）。
- アプリが 127.0.0.1 以外で待ち受けていないかは、起動した時点でだけ確かめている。後から開いたポートは捕まえない。上げるなら、ネットワーク名前空間を分けて中継する。ただし、この試作を作った開発環境（Claude Code の sandbox）では unix socket が禁止されており、この方式はそこでは試せなかった。
- 合成トラフィックは、メモ API の形（`/memos`）に合わせて固定している。
- lap 台帳にはロックが無く、工場のコマンドを同時に 1 つしか走らせない前提。
