## 何が言えないか（既知の限界）

- **要約の効果と、やり直しの偶然は分けていない。** 要約を返さない対照の run は置かなかった。ただし、同じ仕様から要約なしで作った 5 周目の 16 回は、この周の 3 つの少数派の点をすべて外していた。2 回目に 3 点がそろって直り、それ以外は何も変わらなかったことと合わせると、偶然の変化で説明するのは難しい。それでも、対照による確認ではない。
- **条件はやさしい。** 少数派の点はどれも独立した 1 か所の直しで、1 行要約は直す向きをそのまま書いていた（「新しい順」「2 人未満は拒む」「空なら全員」）。要約が曖昧な場合、直しが複数の点にまたがる場合、少数派の答えが既存の作りと絡む場合（例: 端数の配り方を変えると精算の金額が全部変わる）は試していない。
- **少数派の点は、下書き役が選んだもの（作成担当は選んでいない）。** 両方の組が「新しい順」を選び、2 組は完全には独立していない。点ごとの集計で補った（上の「計測 (1)」）。
- **「少数派か」の裏付けは、5 周目の 16 回だけ。** 同じ仕様・同じ系統のモデル（opus と sonnet）の作る役である。
- **LLM 判定は少数派の点を問題にしなかった。** 決定的テストが無ければ、1 回目で出荷していた。この周の結果は、AND の判定を前提にしている。
- **run は 6 本、統計的な検定はしていない。** 判定は事前登録の線による記述である。
- **入口の確認は工場の外で、作成担当が手で回した。** 参照実装の切り替えと、前の周の commit が手元にあることに頼っている。
- **1〜5 周目から引き継いでいる限界。** lap 台帳にはロックが無い。作る役は認証トークンを読める。合成トラフィックはメモ API の形のままで、本番の観測にはほとんど意味が無い。

## 次の周への提案（判断はオーナー）
