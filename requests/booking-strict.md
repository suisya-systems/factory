# Request: booking meeting rooms

An HTTP API for booking a company's meeting rooms. It runs locally only (never exposed publicly). Every request and response body is JSON. Ids are strings the server assigns.

- Times are ISO 8601 strings with an explicit offset (for example `2026-11-02T09:00:00+09:00` or `2026-11-02T00:00:00Z`). The server returns every time in `+09:00` (Asia/Tokyo; Japan has no daylight saving time), formatted `YYYY-MM-DDTHH:MM:SS+09:00`. A time without an offset is 400.
- `POST /rooms` with `{"name": string, "capacity": integer}` registers a room. The name is 1 to 50 characters and unique (case-insensitive: "Room A" and "room a" are the same name, 409); capacity is 1 to 100. 201 with `{"id", "name", "capacity"}`. `GET /rooms` lists rooms in the order registered.
- `POST /bookings` with `{"roomId", "start", "end", "bookedBy": string, "people": integer}` books a room. A booking is the half-open range [start, end): it includes `start`, excludes `end`. Start and end must fall on a quarter hour (minute 00, 15, 30 or 45, second 0); the length is 15 minutes to 4 hours; start and end are on the same Tokyo calendar day, between 08:00 and 22:00 Tokyo time inclusive (a booking may end at exactly 22:00). `people` is from 1 to the room's capacity. `bookedBy` is 1 to 50 characters. 201 with `{"id", "roomId", "start", "end", "bookedBy", "people"}`.
- Two bookings of the same room overlap when each starts before the other ends; a booking that ends exactly when another starts does not overlap it. A booking that would overlap an existing booking of the same room is 409 with `{"error": string, "conflictWith": bookingId}` (the earliest-starting conflicting booking).
- `PATCH /bookings/{id}` with any of `start`, `end`, `people` moves or resizes a booking; the same rules apply to the result, and the booking does not conflict with itself. 200 with the booking. `DELETE /bookings/{id}` cancels it (204); a cancelled booking is gone (404 afterwards) and frees its time.
- `GET /rooms/{id}/free?date=YYYY-MM-DD` returns 200 with `[{"start", "end"}, ...]`: the maximal free ranges of that room between 08:00 and 22:00 Tokyo time on that day, in time order (a day with no bookings gives one range 08:00 to 22:00; a fully booked day gives `[]`).
- `GET /rooms/available?start=..&end=..&people=N` returns 200 with the rooms whose capacity is at least N and that have no booking overlapping [start, end), ordered by capacity ascending, then by name (case-insensitive), as `[{"id", "name", "capacity"}, ...]`. The range must satisfy the same time rules as a booking (400 otherwise).
- Errors: invalid JSON, a missing or wrong-typed field or query parameter, or a value breaking the rules above is 400; an unknown room or booking id is 404; a conflict is 409. Every error body has `"error": string`.
- Data is kept in memory; it does not have to survive a restart.
