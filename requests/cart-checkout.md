# Request: a shop page with a cart, coupons and checkout

A small shop app for one shopper, used locally only. It has an HTTP API (every request and response body is JSON) and a page at `/` that works only through that API. Amounts are whole yen. Data is kept in memory; it does not have to survive a restart.

## API

- `POST /products` with `{"sku", "name", "category", "price", "stock"}` adds a product: `sku` 1 to 20 characters and unique (409 if taken), `name` 1 to 40 characters, `category` 1 to 20 lower-case letters, `price` 1 to 100,000, `stock` 0 to 1,000. 201 with the product. `PUT /products/{sku}/stock` with `{"stock"}` (0 to 1,000) sets the stock; 200 with the product. `GET /products` returns 200 with the products in the order added.
- `POST /coupons` with `{"code", "percent", "minSubtotal", "category"}` adds a coupon: `code` 1 to 12 letters or digits, stored upper-case, unique ignoring case (409 if taken), `percent` 1 to 50, `minSubtotal` 0 to 1,000,000, `category` a category or null. 201 with `{"code", "percent", "minSubtotal", "category", "used": false}`.
- **The cart.** `GET /cart` returns 200 with `{"lines": [{"sku", "name", "category", "price", "qty", "lineTotal"}, ...], "subtotal", "coupon", "couponProblem", "discount", "shipping", "total"}`. Lines are in the order their products first entered the cart; `lineTotal` is `price × qty`; `subtotal` sums the line totals.
- `PUT /cart/lines/{sku}` with `{"qty"}` (0 to 1,000) sets a line; 0 removes it; more than the product's stock is 409. 200 with the cart.
- **The coupon.** `PUT /cart/coupon` with `{"code"}` attaches a coupon, matching the code ignoring case (unknown is 404, a used coupon 409), replacing any attached before. `DELETE /cart/coupon` detaches it. Both answer 200 with the cart. `coupon` is the attached code or null. The coupon applies while `subtotal` is at least its `minSubtotal` and, if it has a category, the cart has a line of that category; otherwise `couponProblem` is `"min"` (checked first) or `"category"` and the discount is 0. It is re-checked after every cart change. `couponProblem` is null when no coupon is attached or it applies.
- **Amounts.** `discount` is `percent` of the line totals it covers (all lines, or its category's), rounded down. `shipping` is 500 when the cart has lines and `subtotal − discount` is below 5,000, else 0. `total` is `subtotal − discount + shipping`.
- **Checkout.** `POST /checkout` refuses an empty cart (409) and a cart where a line's `qty` exceeds its product's current stock (409 with `{"error", "short": [{"sku", "stock"}, ...]}`, each such line in cart order). Otherwise it creates an order `{"id", "lines", "subtotal", "discount", "shipping", "total"}` from the cart as `GET /cart` shows it, takes each `qty` off its product's stock, marks an applied coupon `used`, and empties the cart and its coupon. Order ids are `"1"`, `"2"`, ... 201 with the order. `GET /orders` returns 200 with the orders in order.
- Errors: invalid JSON, a missing or wrong-typed field, or a value outside the rules above is 400; an unknown product is 404; the conflicts named above are 409. A refused request changes nothing. Every error body is `{"error": string}`.

## The page `/`

Names in `code` below are test ids. Buttons are never disabled or hidden. Amounts show as `¥` and the number with thousands commas (`¥12,300`, `¥0`).

- **Products**, in the order added, each with `productName`, `productPrice`, `productLeft` (`3 left`, or `Sold out` at 0) and `addButton`. `addButton` adds 1 to that product's line (a new line has qty 1) and saves it; when the line already holds the whole current stock, nothing changes and `pageMessage` shows `Only {stock} of {name} left`.
- **The cart.** Each line has `cartName`, `qtyInput` (its qty), `lineTotal` and `removeButton`. With no lines, `cartEmpty` shows `Your cart is empty`. `subtotal`, `discount`, `shipping` and `total` show the cart's amounts.
- **Quantities.** The user edits `qtyInput`s and clicks `updateButton`. An input that is not digits only gets `{name}: enter a whole number`; a number above the product's current stock (read at the click) gets `{name}: only {stock} left`. These show in `qtyError`, one element each, in cart order. With any problem nothing is saved and the inputs keep what was typed; otherwise every line is saved (0 removes it) and no `qtyError` shows.
- **The coupon.** `couponInput` and `couponApply` attach a code; `couponRemove` detaches it. While a coupon is attached, `couponNote` shows `{CODE}: -¥{discount}` when it applies, otherwise `{CODE} needs a subtotal of ¥{minSubtotal}` or `{CODE} needs a {category} item`. An unknown or invalid code shows `pageMessage` `Unknown coupon code`, a used one `{CODE} has already been used`.
- **Checkout.** `checkoutButton` first checks and saves the `qtyInput`s as `updateButton` does; with a problem it also shows `pageMessage` `Fix the cart before checking out` and orders nothing. Otherwise it checks out: an empty cart gives `pageMessage` `Your cart is empty`. On success `pageMessage` shows `Order {id} placed: ¥{total}`, the cart is empty, `couponNote` is gone and each `productLeft` shows the new stock.
- `pageMessage` shows only the message of the last click; a click that sets none clears it. After every click the page shows the products and cart as the API gives them, except inputs kept after a problem. Reloading shows the saved cart.
